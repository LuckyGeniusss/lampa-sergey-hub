## Ограничения и оставшиеся проверки
1. **Иконка плитки Projectivy**: APK уже содержит правильную широкую графику, но плитка продолжает показывать прежнюю квадратную картинку из кеша лаунчера. Перезапуск Projectivy и перезагрузка Fire Stick не помогли. Пункт ручного изменения значка отмечен как Premium; не обходить лицензию и не очищать данные ради одной иконки. После официальной активации можно заменить её штатно. Официальная покупка Premium уже отслеживается отдельной задачей.
2. Воспроизведение всех 15–20 VOD-источников на каждом фильме **не** подтверждено. Нужно проверять конкретные HLS/MP4, озвучки, серии, субтитры; счётчик обнаруженных провайдеров не приравнивать к работоспособным видео.
3. Проверка FFmpeg выполнена на Mac mini в Ирландии; на Fire Stick не проверены все 2339 каналов. Некоторые могут иметь геоблокировку или ухудшиться позже.
4. Внешняя инфраструктура (Render, GitHub Actions, провайдеры) может изменяться; автоматический workflow может завершаться ошибкой при геоблокировке источников. Защитные проверки не допустят публикации явно неполного списка.
5. Платная лицензия Projectivy не приобреталась. Загрузчик Projectivy/Wolf и системные Amazon-пакеты не отключались и не удалялись.

## Исправление воспроизведения Wazo Online 1.5.9 — 31.10.2026

- Сообщённая пользователем ошибка: `details [manifestLoadError] fatal [true]` (фатальная ошибка получения HLS-манифеста); также встречается «Неможливо отримати посилання» (не удалось получить видео URL).
- Причина на стороне клиента: положительный результат поиска провайдера ошибочно считался достаточным для просмотра; ошибки получения URL не инициировали смену источника; сохранение провайдера происходило до декодирования видео.
- Изменён плагин `js` и синхронные алиасы `p.js`, `plugin.js`, `online.js`, `u.js` до версии **1.5.9**. Хук `Lampa.PlayerVideo.listener` отрабатывает фатальные ошибки при запуске видеопотока Wazo, временно исключает отказавший источник для конкретного фильма и возвращает к выбору следующего. Ошибки получения URL обработаны так же. После события успешного воспроизведения (>2 с) сохраняется выбранный провайдер; обычный IPTV не затрагивается.
- Добавлен `tests/playback-failover.js`: проверки фатальной/нефатальной ошибки, однократного переключения, успешного проигрывания, устаревшего сообщения, закрытия плеера. Node syntax и plugin static tests прошли.

Для «Матрицы» попытка Twoembed привела к переключению на Zagonka. После выбора Zagonka плеер вывел `[Player] start playing`; экран показал видео 1281×690 с заполнением буфера ~33 секунды.
- Изменения в GitHub `596b5feacebd18d31b0454ccebb69aefd2e5b233`. Изменение APK не требовалось: плагин загружается из GitHub Pages.
- Ограничение: этот патч не исправляет недоступные сторонние HLS-серверы, а корректно обрабатывает их отказ. Оставшиеся провайдеры не проходили все индивидуальную проверку и могут требовать авторизацию, геодоступ или обновление upstream-API.
